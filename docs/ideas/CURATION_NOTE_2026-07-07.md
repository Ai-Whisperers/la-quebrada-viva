## Why we're not deleting the auto-fill layer

Per the 2026-07-03 audit (`docs/audit/CRITIQUE_V2_ADDENDUM.md`), the
auto-fill layer was kept for 4 reasons:

1. **Auditability**: shows the original 109-idea brainstorm state pre-research
2. **Coverage gaps**: some auto-fill ideas were not picked up by R-items closure
   (mostly low-priority operations stuff like `i13_cost-per-m2_benchmark`)
3. **Renumbering history**: some auto-fill IDs (f01, f02, f07) are now part of
   the W0.x canonical Wes-action list
4. **Don't-break-history**: a refactor pass at this scale has been
   deferred 4 times in the doc

## What this pass does

For each auto-fill file, prepend a `> STATUS: SUPERSEDED` banner pointing at
the canonical replacement (2026-07-06 R-LQV catalog or 2026-07-03 reviewed
catalog). After this pass:

- `git grep "STATUS: SUPERSEDED" docs/ideas/_archive` returns 46 hits
- The auto-fill layer is **intentionally unmaintained** — no future session
  should "fix" or "enrich" these files
- New research lands in `docs/research/RESULTS/` (R-LQV catalog) or
  `docs/people/wes/WES_ACTIONS.md` (W0.x tracker), never in the auto-fill layer

## Curation script

The banner-injection is a 1-liner per file. A future pass can run:

```bash
for f in docs/ideas/_archive/2026-06-30_autofill/*/*.md; do
  if ! head -1 "$f" | grep -q "STATUS: SUPERSEDED"; then
    (cat << 'EOF'
> **STATUS: SUPERSEDED 2026-07-07.** This auto-fill stub is preserved for
> history. The active research lives in:
> - `../../research/RESULTS/R-LQV_CATALOG_2026-07-06.md` (15 LQV research batches)
> - `../../research/strategy/RESEARCH_GAPS.md` (R-items tracker, 28/28 closed)
> - `../../people/wes/WES_ACTIONS.md` (W0.x canonical Wes action list)
> **Do not edit this file.** Add new research to `docs/research/RESULTS/`.

EOF
    cat "$f") > "$f.tmp" && mv "$f.tmp" "$f"
  fi
done
```
